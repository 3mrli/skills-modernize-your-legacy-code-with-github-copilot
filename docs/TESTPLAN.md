# COBOL Account Management Test Plan

This test plan records the current behavior of the COBOL account-management application for business stakeholder validation. Execute the cases in order within a single application run where noted. `Actual Result` and `Status` are intentionally left for execution; use `Pass` or `Fail` for status after each case.

| TC-021 | Check an amount exceeding the numeric field capacity | Start a new run. | At a credit or debit prompt, enter an amount above the six-integer-digit COBOL field capacity, such as `1000000.00`. | The current implementation uses `PIC 9(6)V99`; observe whether the runtime rejects, truncates, or otherwise handles the value. | TBD | Not Run | Define a Node.js maximum amount and overflow behavior. |

## Stakeholder Decisions To Record

- Should zero-value credits and debits be accepted or rejected?
- What validation and error message should apply to negative, malformed, or oversized amounts?
- What precision and maximum amount should the Node.js application support?
- Should balances persist across application restarts, and should multiple accounts or transaction history be introduced?
